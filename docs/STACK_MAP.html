How the Assistant decides

Every message on the Assistant runs this list from the top, and the first match wins. The router reads only your own words, never a pasted document or search results, so a PDF that mentions “video” can't start a render. Videos, picture edits and new background jobs ask you to confirm first.

Sharing one GPU

The rules that keep chat, renders and the background agent from pushing each other off the card.

One queue for everything

Chat, code, pictures and video all take the same lock. A message sent mid-render waits its turn and shows how long it has waited.

“Waiting for the GPU… 1m 20s”

Swaps cost seconds

Chat and the coder can't share the card, so switching costs a swap each way. The agent's 64K tag is a second runner of the chat weights and pushes chat out.

chat ↔ code 6–12 s · chat reload 22.7 s

Heat gate

After getting the lock and before loading a model, it checks the card's temperature. Too hot and it waits, holding its place in the queue. An unreadable sensor never blocks.

pause at 85 °C · resume at 75 °C

Models leave quickly

Ollama unloads a model 60 seconds after it was last used, so ComfyUI gets room. The pipe also frees ComfyUI's memory before small prompt helpers run.

OLLAMA_KEEP_ALIVE=60s

The agent waits for a free card

gpuguard holds back scheduled jobs while ComfyUI has work or a big chat model is loaded. A due job is put off to the next minute, never dropped.

checks ComfyUI /queue and Ollama /api/ps

ComfyUI stays up when idle

homelab-maint checks every 5 minutes. If ComfyUI's queue is empty but it still holds memory, it restarts the container, which unloads the models. Until today it stopped the container after 15 idle minutes, and picture tools failed until someone started it again.

restart above 3,000 MiB VRAM or 4,000 MiB RAM, two checks in a row

Background jobs, start to finish

“Watch this price for two weeks and text me under $50” becomes a real scheduled job. The model writes text, and plain code does the checking and the sending, so a model that goes quiet can't silently drop an alert.

You ask

Press Task, or say “track… every…”. A job with a schedule is what turns a message into a watch.

Confirm and contact

You confirm. If it should text you and has no number on file, it asks before scheduling anything.

Agent makes the job

hermes gateway on :8642 creates a cron job. The pipe checks the scheduler really has it and fixes its shape.

Job runs when the card is free

On hermes-genesis:agent at 64K context, using searxng-hermes on :8889. Prices are compared in Python.

It writes a result

Every run ends with a LOG: line, plus an ALERT: line when your condition is met.

Delivery sends it

hermes_delivery.py checks every minute: email and a text, 3 retries 5 minutes apart, each attempt recorded.

Cancel from the alert

The cancel.ohmz.cloud link pauses or cancels with no login, and cleans up everything the job left.

The stack also watches itself: a watchdog every 5 minutes (gateway, API, delivery timer, backups, FlightClaw, public gate, scheduler heartbeat), a search check every 30 minutes on both SearXNG instances, and an alert whenever a service fails. Most checks need two failed runs before they alert. DOWN sends a text and an email, DEGRADED sends only an email.
